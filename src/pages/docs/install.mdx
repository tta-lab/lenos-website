# Install

Lenos is installed with the release bootstrap script. It supports macOS and Linux on x86_64 and arm64.

## One-line install

```bash
curl -fsSL https://github.com/tta-lab/lenos/releases/latest/download/install.sh | sh
```

The script downloads the `lenos-installer` release archive for your platform, installs binaries to `~/.local/bin`, and writes starter config files only when they do not already exist.

Add `~/.local/bin` to your `PATH` if needed:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

After installation, run `lenos --help` to verify. Configure model keys in `~/.lenos/config.json`, workspace `.lenos/config.json`, or environment variables documented in [configuration](/lenos-website/docs/configuration).

## Included tools

The installer installs Lenos plus the Organon CLIs that Lenos prompts use. This is the tool layer: plain shell commands instead of hidden adapter APIs.

- **`lenos`** — the terminal agent runtime.
- **`src`** — tree-sitter symbol-aware code reading and editing. Parses files into an AST, assigns each symbol a 2-char ID, edits by symbol reference rather than line number or text match. Works with Go, Rust, TypeScript, Python, and many others.
- **`web`** — web search and fetch.
- **`skill`** — skill discovery CLI used by lenos and the broader ttal ecosystem (`skill get <name>`, `skill list`).
- **`project`** — project lookup CLI used by local workflows and agent context.

The landing-page examples that cite `src edit`, `web search`, `skill get`, and `project get` refer to these binaries. The same command surface is visible to humans and agents.

## Sandbox config

Lenos links the Temenos sandbox SDK directly. There is no separate sandbox daemon to install. The installer writes a starter Temenos config to `~/.config/temenos/config.toml` when that file does not already exist.
